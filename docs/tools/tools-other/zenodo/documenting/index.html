    Documenting a Zenodo Package¶

    Overview

    This is the Documenting a Zenodo Package page, part of Zenodo → Other Tools in the A-LIFE RDM collection.

    Before archiving in Zenodo, good documentation makes your dataset findable, citable, and reusable. This page covers:

    • Metadata — the structured fields you will fill in during archiving
    • README — the human-readable file you prepare before uploading

    Authors: Irene Martorelli, Brett Olivier — Last modification: 2026-06-27 — Version: 0.1.0

    Two layers of documentation¶

    A well-documented Zenodo package has two complementary layers:

    • Metadata — structured fields (title, creators, description, licence, resource type, etc.) that you fill in directly in the Zenodo interface when creating a record. Metadata is machine-readable, feeds search engines and data catalogues, and makes your dataset findable and citable. Some fields are mandatory; others are strongly recommended.
    • README — a plain text file that you write and include inside your uploaded files (or ZIP archive). It is human-readable and describes the content of the files, how the data was collected, and how to use it. The README is not enforced by Zenodo, but it is strongly recommended and required by the A-LIFE checklist before archiving.

    Metadata answers "what is this dataset?" for search engines and catalogues. The README answers "what is in these files?" for the person who downloads them.

    1. Metadata¶

    When you create a new upload in Zenodo, you fill in a metadata form as part of the archiving process. The form includes three categories of fields: Basic (mandatory), Recommended, and Other (optional).

    Getting the metadata right before you start archiving will speed up the process and ensure your dataset is properly described from the moment of publication.

    Key things to prepare in advance:

    • Title — a clear, descriptive title for the dataset (not just "data")
    • Creators — names, affiliations, and ORCID identifiers for all contributors
    • Description — a concise summary of what the dataset contains and what research it supports; you can copy the key content from your README
    • Resource type — choose the type that best fits (dataset, software, poster, etc.)
    • Licence — decide which licence applies to your data before uploading; check with your data steward if unsure
    • Related publications — link your dataset to any associated article using its DOI

    2. README¶

    A README is a plain text file (.md or .txt) that describes the content of your dataset. Include it inside your ZIP archive or upload it as a separate file alongside your data files.

    What a good Zenodo README should cover:

    • A short description of the dataset and what research question or publication it supports
    • A list of the files or folders included, with a brief description of each
    • Information about how the data was collected, generated, or processed
    • Software, tools, or dependencies needed to open or work with the files
    • Licence information
    • Contact details

    Tip

    Copy the key description from your README into the Zenodo Description field when filling in the metadata form — this ensures the content is visible on the dataset landing page without requiring a download.
